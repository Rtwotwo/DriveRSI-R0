# 以场景为单位的语义标签与聚类池

当前阶段：一份真实 navtrain 场景的百炼示范。标签等待用户审核；不批量标注、不写生产索引、不替换现有聚类池。本次未对 navtrain 运行学生评分。

## 精简主文件

`sample.json` 当前采用 `driversi.scene_label_summary.v1`：一个短 caption 加道路、自车行为、速度汇总、交互、视觉补充五组字段。主文件不再嵌入 `timeline`、逐时刻 `world_xy_m` / `heading_change_deg`、对象轨迹、长证据清单或多份重复的检索文本。均速与范围按既有源标注计算，不凭空补充起末速度或加速度阶段。

完整的 `driversi.scene_labels.v1` 记录保存在 `evidence_ref` 指向的 `audit/labels-<identity>.json`；内容哈希供核对，原始坐标和事实仍可查。旧主文件在 `superseded/<sha256>.json` 保留。下表描述的是完整证据契约，精简主文件只投影其中所需信息。

维护实现为 `src/data/catalog/scene_label_summary.py`，显示属性选择在 `src/config/data/scene-labels/summary-profile.json`。`scene_label_jobs.publish` 统一生成完整审计和精简主文件。tentative、unknown、未审核与离线全片范围保留；精简不会自动使标签取得检索/训练资格。

此次仅改变输出组织，`context.json`、原API请求和回执不变。JSON文件减少的字节数不等于API输入token或账单下降；发送侧精简需另行验证。

## 数据单元和范围

一个记录对应一个场景 token 的连续 0–7 秒窗口，锚点为第 2 秒。输入包含真实多相机图片、源日志导出的自车与参与者轨迹，以及可用的地图事实。轨迹插值是离线表示，不冒充新增传感器观测。

本示范采用四相机、四个真实时刻（相对锚点约 −2、0、+2.5、+5 秒），同时读取完整 71 个白膜状态并按 0.5 秒整理轨迹。少量图像只能支撑可见证据；不能据此证明每个中间时刻的外观或短暂事件。报告记录总对象数与被摘要对象数，不能把缺失标注当作物理不存在。

完整窗口标签使用 `retrospective_full_clip`，`future_included=true`、`online_policy_input=false`。历史检索必须重新使用锚点之前的输入标注；不能从完整描述中简单删除未来时间词后假装变成历史描述。

## 一份标签的组成

|字段|职责|来源与约束|
|---|---|---|
|scene / information_scope|token、父日志、划分、时间窗和使用范围|程序绑定，不让 VLM 决定|
|measured_summary / context.json|位移、航向、状态时间、各参与者轨迹、地图可用性|日志计算，记录插值与缺失；数值不由语言模型生成|
|labels.summary|简洁、可区分的场景概述|VLM 联合理解图像和事实|
|labels.facets|道路背景、几何、自车运动、交通配置、交互、可见性、环境、标线八类属性|每轴允许多标签；未标注不等于否定|
|labels.events|谁在什么时间做了什么，关联对象及证据|带事件类型、对象别名、时间区间；不跨缺标区间认证连续事件|
|distinctive_features / unknowns|场景差异与具体未知项|不强行制造难例，不把因果猜测写成事实|
|evidence_ids / fact_ids|图像相机和真实时间、结构化事实来源|检查引用存在；引用有效不等于内容准确|
|draft_retrieval|场景文本与可过滤标签|仅为草稿，审核前 indexable=false|
|draft_clustering|多标签语义与事件序列|不让 VLM 发明簇编号；审核前禁止写池|
|review|格式、事实复核和批量批准状态|分开记录；JSON 合格不能替代事实审核|

VLM 的 `supported/tentative` 是模型自报的证据强度，不是校准后的概率，更不是外部审核结论。`sample.json` 保留真实原始输出；另附字段复核文件，不偷偷改成“完美标签”。

## 两个池共享类别，而不是匹配独立编号

设计采用两层组织：

1. **可重叠的语义组**：道路与任务、参与者配置、交互及触发条件。直行、施工邻接、驶过静止车辆可以同时出现。相同应对方式、仅外观不同的场景不自动拆成不同驾驶能力。
2. **自动发现的统计簇**：在训练侧拟合表示及原型，用于发现未覆盖模式。固定版本后，将 navtest 分配到同一表示和类别体系。两边分别存成员，未知场景保留 unknown；不把两个独立 K-means 的 cluster_17 认为对应。

场景可以关联多个语义组及多个候选原型。事件须保留时间顺序和参与者关系，不用普通词袋代替交互。视觉、语义、轨迹通道分别保留可用性与证据，融合策略留给对照验证，不提前指定一套通用权重。

计划的检索流程：能力需求 → 训练池相关语义组与簇 → 多通道召回 → 按交互相关性、多样性、资产支持与预算排序。caption 不能证明失败原因；不要求 navtrain 学生评分。训练候选只返回训练 token，测试成员及逐场景失败记录留在隔离的评测侧。

现有 `scene_clusters.py` 是历史统计与视觉向量的基线。本示范没有改变该算法或宣称新语义簇已构建全库。后续须用标注的场景对检验同类交互相关性、长尾覆盖及合成成功率，才能报告 Recall@K 或优于视觉检索。

## 如何服务 Harness 技能

类别不是技能。可执行技能还须包含适用条件、检索/诊断程序、输入输出、预算、验收与退出条件。Harness 可据已审核类别选择技能；每次执行记录生成器版本、物理与视觉准入、数据血缘，以及后续配对收益与成本。失败原因、模型版本与评分独立保存，不反向污染场景 caption。新版类别须保留旧版本映射和未匹配成员。

## 白膜共用入口

批量白膜仍使用 `scripts/data/run_whitebox_delivery.py` → `src/rendering/whitebox/delivery.py`。连续日志的位置、朝向、尺寸由 `conditioning.py` 共享时间支撑，尺寸版本为 `source_bracket_linear_v1`；闭环执行尺寸为 `executed_physics_unmodified`。保留对象身份、原始观测时刻与缺标区间，不跨空缺补车。旧版视频不能仅改元数据作为新结果。

新标签入口会检查当前尺寸采样版本和源状态审计，避免用已淘汰的白膜表示生成结构化输入。

## 代码与配置

- `src/data/catalog/scene_labels.py`：场景事实、响应契约、证据与时间校验、草稿产物。
- `src/data/catalog/scene_label_jobs.py`：复用现有私有百炼客户端；默认只准备输入。
- `src/config/data/scene-labels/{taxonomy.json,response.schema.json,prompt.md}`：版本化词表、机器契约、提示词。
- `scripts/data/label_scene.py`：薄命令入口，已注册到脚本目录。
- `exp/scene-semantic-label-v1/`：本次实图、输入上下文、回执、示范与复核；凭据不在其中。

显式 `--execute` 仅请求一个场景、一个配置模型，单请求上限，不自动重试。只读取用户指定的受限凭据路径，复用已有客户端的传输与脱敏机制。没有批量 release 参数；用户批准设计后，仍需独立实现逐字段质检、抽查和批量预算。

## 本示范的复核边界

真实 API 回执是格式有效、待事实复核的草稿。大部分可见场景属性有支持；路缘白线描述、交通锥与图片的对应、事件的精确边界等需修订。当前不知道自车对应车道，也没有图像对象与轨迹别名的可靠外观绑定，因此不能输出确证切入、合法让行、某颜色车辆的轨迹或原因诊断。

结构化上下文较长；本次单请求用了 34,217 输入 tokens（其中图像 5,024）、1,519 输出 tokens。不能直接复制这个输入方式跑 103k。批量前应把轨迹编码压缩成紧凑数组及可复核事件摘要，并做保真对照；保留完整原始事实供审计，不把压缩成本转嫁为事实遗漏。

## 复审后的时间与恢复约定

`time_span_s` 是 VLM 提出的观察/相遇窗口，不是已检测出的动作起止。`event_time_contract` 明确这一点；聚类草稿中采用 `observation_window_s`，`action_interval_s=null`，不把该窗口长度作为动作持续时间特征。真正的切入、横穿等动作起止，后续需要地图关联和执行式事件检测。

API 接收成功和当前发布校验分别记录。`publication.json` 是当前解析器状态；旧缓存重新解析失败时，旧 JSON 按哈希保存在 superseded，当前 sample 显式变为 rejected，而不会留下一份看似仍有效的旧标签。

归档主文件保持原字节，`superseded/<sha256>.references.json` 说明其内部相对引用仍以原实验目录为基准（`reference_base=..`）。精简视图的 uncertain 同时保留暂定属性、事件与摘要。
