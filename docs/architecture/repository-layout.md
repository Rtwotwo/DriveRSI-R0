# 项目分层与文件归属

目录数量本身不代表混乱。此前主要问题是重复启动别名、一次性实验页面与正式工具混放、脚本被当作公共模块导入，以及文件缺少维护状态。

|位置|唯一职责|不应放入|
|---|---|---|
|src/|平台实现：数据、物理、渲染、训练、评测、Harness、可视化|实验输出、临时启动脚本|
|src/config/|按功能分类的版本化参数和协议|运行结果、密钥|
|src/vendor/|保留许可证和版本信息的上游源码|平台自有业务和实验产物|
|agents/|当前支持的模型实现及适配|通用渲染SDK、数据平台逻辑|
|scripts/|按功能分类的命令入口与维护工具|新公共算法、整套实验UI|
|tests/|对应领域的合同及回归测试|真实训练产生的数据|
|docs/|分类文档与研究记录|原始日志、权重|
|assets/|人工维护、可复用的插图等资源|临时渲染结果|
|lib/retrieval/|分库管理的原始及新合成检索资产、连续矩阵、来源清单|实验查询结果、公开测试明细|
|weights/|下载的初始模型和backbone|新训练检查点|
|exp/|运行配置快照、检查点、日志、评测和反馈|长期源码|
|outputs/|历史证据、数据和本地预览链接|新实验默认输出|
|clones/|待整理的上游来源与原生构建/数据准备依赖|新增运行时Python跨目录导入|
|.venv/、.venvs/|平台与原生模型隔离环境|项目业务代码|

`driversi.egg-info` 是当前开发安装的包元数据；`.pytest_cache`、`.ruff_cache` 是工具缓存。它们不是业务模块，也不能只凭以点开头就当成无用文件。

目前 clones 中仍保留 PufferDrive/raylib 构建输入，以及部分模型/渲染数据准备来源；本轮不猜测它们可删除。outputs、exp 的历史路径仍被真实回执和可视化引用，整体搬移会使封存证据失效，因此不改写。

## 已落实的整理

- 根目录不再新增脚本或配置；常用入口、文档和代码路径可从项目README查找。
- scripts根目录26个旧别名移除；27个历史报告工具归入legacy/reports。
- 公共数据编排、发布校验、GS窗口和视觉审查实现迁入所属src模块，脚本仅调用main。
- 文档按architecture/models/training/rsi/data/rendering归类，既有design和research继续保留。
- scripts/catalog.json记录全部现存入口的用途、实现和维护范围；目录合同由架构测试检查。

这是一轮行为保持的组织改造，不证明已有模型、训练或合成流程获得新收益。历史报告工具保留用于审计，不再成为新增实验的默认页面模板。
