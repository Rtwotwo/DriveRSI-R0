# Harness恢复、训练血缘与当前工作台

入口仍是 `python -m driversi.rsi.experiments.continual_curriculum --help`。当前课程启用 `operations-policy.json` 与 `storage-recovery-policy.json` 后，执行器自行识别已登记的终止故障，核验原始输入、已结束任务和剩余预算，再继续同一波。它不负责自动编写任意修复代码；未知执行和耗尽预算仍须明确停止，不能伪装运行。

PNG使用内存无损编码、同文件系统原子不覆盖发布和fsync，避免每帧临时目录的NFS清理竞态。已发生的单分支PNG目录清理故障，仅在后处理未准入、工作进程已结算时，允许在新目录重做未完成渲染。原轨迹不重新生成。最多两次修复，共享原批次耗时预算；同波截止时间固定，恢复不获得新六小时。

`dataset/manifests/curriculum-lineage.json`按问题、navtrain来源、原候选、数据包及训练回执组织现有数据，原SimScale/OpenScene目录不搬迁。历史样本保留，未知旧血缘不猜测。准入总数和跨策略互异数分别记录；按当前差异规则逐源复核后才累计配额，每源带入生成的旧样本不超过该源目标，防止某一源超额耗尽其他源名额。

训练从每来源合格数据中选定完整配额。跨轮样本通过 `reused_executions` 绑定原始生成报告和原计划，继续使用原生血缘核验，不修改旧分支。训练参数按数据量、轮次和既定GPU池生成：初轮4遍，未解决时最多增加到8遍，并受更新上限限制；学习率保留原生batch缩放。规则与反馈持久化，尚未证明已经学得最优超参数。每轮晋级仍须目标改善、全量navtest和安全保持检查。

固定可视化平台读取Harness写出的 `current-operations.json`。只显示当前问题、来源、产量、配方、资源和恢复记录，不新建仪表盘、不恢复公网发布、不安装定时监控。计划曝光与原生训练已观测消费分开显示。

清理只接受项目精确 `dataset` 路径，仅删除没有样本/准入/暂存对应项且未被持有的空锁文件；图片、日志、样本、准入记录、清单和历史数据均保留。
