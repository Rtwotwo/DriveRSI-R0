# DriveHarness 的技能与自迭代边界（2026-10-26）

## 调研结论与证据范围

RSI 不要求底层必须是 VLA。它要求经验真的改变下一轮改进过程，并用独立结果验证这种改变有用。VLA 提供可学习的视觉—语言—动作接口，但安装一个技能文档不等于模型参数获得能力。DriveRSI 应同时管理权重改进和执行系统改进，分开报告。

## 当前平台已具备和缺少什么

现有能力反馈、训练库检索、教师技能、同分支物理/视觉/语言准入、原生配对训练、跨进程恢复和服务记忆都可复用。`capability_skills` 保存先验适用条件及生成身份；`SceneSkillMemory` 保存场景诊断；`ServiceMemory` 保存节点级执行和学习结果。未证明的是跨场景技能的因果收益、在线驾驶干预接口，以及相同成本下迭代方法比固定策略更有效。

已有AUGUstus模型配置声明 `online_control=false`，原生SFT配置为 action-first。其动作之后生成的语言不能倒过来引导同次动作。先验语言可作为新的实验干预，但必须验证模型确实使用且不会恶化驾驶；本轮保持原生prompt和模型不变。

## 三层分工

1. **原生驾驶执行层**：AUGUstus原生视觉输入、动作输出与执行器。保持时钟、历史、坐标、控制语义。每次动作不能依赖未来真值或测试评分缓存。
2. **事件驱动的驾驶辅助层（下一阶段，尚未启用）**：当前历史条件触发，选择已验证的观察、重新规划、候选检查或恢复程序。每个程序必须有输入权限、返回类型、调用次数/耗时上限、终止和回退。失败时回到受控执行器，不能无限询问LLM。输出记录原生建议、实际执行动作和接管原因。特权教师只能在模拟研究或数据生成中使用，不能混称可部署感知能力。
3. **离线改进层（当前实施）**：评测汇总 → 训练来源能力检索 → 已有证据核查 → 选定训练/生成干预 → 真实配对实验 → 独立收益/退化与成本 → 更新实验记忆。此层可以耗时，但预算和停止条件必须明确。

## 技能应保存什么

长期技能的契约为：技能ID/版本、用途（离线服务或在线辅助）、适用可观测条件、支持模型/父权重摘要、输入/输出产物、固定工具与参数、最大调用和耗时、独立成功条件、失败分类/回退、训练来源继承、证据ID、验证级别。自然语言说明帮助人和LLM理解；代码和结构化契约决定可以执行什么。

候选 → 小样本验证 → 跨来源验证 → 冻结发布，是技能的生命周期。一次成功只增加证据，不能跳到发布。失败也要记录，不应只把成功案例写入长期记忆。策略或评分协议变了，旧经验先降为待复核建议。训练结果可用于修订策略，但不能倒填成“生成前已选中这个技能”。

当前注册的 `same_anchor_relabel`、`reactive_new_history`、`bounded_perturbation_history` 是离线生成技能；本轮新增的 bounded intervention campaign 调用既有 AUGUstus paired service，不新增驾驶控制器。自适应选择的第一版是明确的确定性优先级策略，未声称学习型bandit已经有效。

## 评测与检索隔离

评测侧逐token明细留在内部评测证据；调度器只使用核验过的汇总和结果状态。检索器访问navtrain库的结构化条件、审核caption、已有模型结果及资产可用性，所有派生样本继承训练源。当前禁止重新启动navtrain学生评分；旧评分只适用于对应权重和协议，不伪装成新模型结果。

正式测试反馈用于开发即属于adaptive evaluation；当前锁定navtest小样本不能证明未参与开发的泛化。后续固定评测计划，保留完整基准和未调参样本，不能反复只挑表现好的测试场景。

## 有限自迭代执行器

`src/rsi/experiments/intervention_campaign.py` 在执行前封存有限候选程序、父权重/评测身份、假设、优先级与总优化预算。调用原有 `augustus_round`，不实现第二套训练器。

- 学习无收益：选择尚未执行的已声明干预，不修改已完成实验。
- 平台/数据/恢复/评测阻塞：停止并返回对应修复节点，不把错误算作模型失败。
- 出现正向pilot：停止并要求扩大独立验证，不在同一小集上自动晋级。
- 完成回执可跨进程恢复；训练、续训和恢复重放都计入预留更新上限。预留值不是实测GPU时间，实际费用仍来自原任务回执。
- 所有实际结果进入既有服务记忆；campaign保存决策、假设、程序版本和引用，支持下一轮追溯。现阶段不自动生成或运行LLM代码，也不自动安装skills。

入口（先prepare既有AUGUstus程序，再封存campaign）：

```bash
.venvs/augustus/bin/python scripts/rsi/run_intervention_campaign.py prepare exp/<run>/campaign-config.json
.venvs/augustus/bin/python scripts/rsi/run_intervention_campaign.py advance exp/<run>/campaign --execute
```

每次advance最多推进一组配对实验；同目录重启复用回执。候选程序必须尚未执行且同父模型、同锁定评测。不同候选预算可以不同，但每个候选内部control/treatment同预算。当前去重只覆盖本campaign的程序和干预ID；跨campaign语义等价配方的重复识别仍需补齐，不能声称所有历史重复都已避免。跨候选差异是实验因素，不是严格同预算的算法优劣比较。

## 如何证明技能和训练分别有效

冻结同一测试协议，比较：M0+H0、M0+H1、M1+H0、M1+H1。前两者测外挂技能收益，中间模型比较测权重收益，最后测交互。进一步比较固定改进配方与自适应配方，在相同初始学生、场景池及总预算下记录新日志收益/退化、合格数据率、时间和成本。单个合成样本、单seed、4个测试锚点只能验证链路，不能证明稳定自进化。

可视化只在 `src/config/visualization/platform.json` 登记聚合字段、训练回执和Harness任务，复用统一工作台。研究、候选配置、审查与实际运行证据保存在 `exp/harness-evolution-v1/`。

## 面向 AUGUstus 的长尾技能：具体执行边界

首批在线技能应围绕可观测、可检验的问题设计，先做影子执行，再做同锚点对照；下面是下一阶段候选，不是已启用能力：

| 候选技能 | 允许的触发证据 | 可测试的干预 | 禁止的捷径 |
|---|---|---|---|
| 遮挡交叉口复核 | 当前与过去相机、当前可见对象、道路连接、感知置信度 | 检查是否需要缩短执行段并重新观测；调用已验证的有限重新规划接口 | 用未来对象真值解释遮挡；把特权教师当车载感知 |
| 静态障碍低进度诊断 | 连续历史内的实际低进度、可见障碍与剩余通行空间 | 区分合理等待、地图/跟踪问题和决策问题；在受限候选中重新规划 | 总分提高就把停车当绕行成功；删除障碍 |
| 合流风险复核 | 当前相对位置、速度及其不确定性，实际候选轨迹 | 检查多个原生候选的执行风险并决定是否继续原方案 | 读取评测缓存里的未来轨迹决定线上动作 |
| 反复恢复失败升级 | 本次任务的真实执行失败与预算消耗 | 停止重复调用；转入人工/离线修复队列，保留失败快照 | 无限查询LLM；修改评分门槛后放行 |

所有技能必须先声明它实际能调用的模型接口。AUGUstus 当前没有注册以上在线工具，不能把这些名字写入提示词就当作实现。动作前额外语言提示、原生多候选选择、执行段长控制是不同干预，必须分别测量；不能同时改动后只归功于“记忆”。多候选涉及更多推理与检查成本，和单次原生推理比较时也要报告这个成本。

持久记忆保存的是适用条件、执行程序、证据与失败边界。单次驾驶状态、缓存和短期轨迹历史放在 episode state，退出场景即结束；不能把某个测试token、坐标或未来事件记成下一次驾驶提示。未知条件下技能应明确拒绝，而不是强行套用已有经验。

离线监督层每轮至少留下：父模型摘要、来源归属、检索查询及候选集版本、使用的已有评分版本、选题假设、生成器与skill版本、拒绝原因、实际训练消费样本、更新次数、恢复证据、评测协议/覆盖、逐项退化、成本、下一步选择与选择时可见的证据。评测侧明细保留私有审计；发布界面和跨split查询仅使用合规汇总。现有campaign只连接已封存的配对训练候选，仍需后续把新的训练来源检索与生成动作纳入同一前瞻候选分配，才能验证整个选择策略的收益。

## 哪些情况下改skill，哪些情况下训练权重

借鉴AdaRSI的归因思路，建议把同锚点诊断结果分成四种可追溯状态：平台执行错误、Harness调用/上下文错误、在已验证调用下持续失败的模型能力缺口、证据不足。当前分数或LLM解释只能提出假设；要用受限干预对照验证，未验证不得强制归为模型缺陷。平台错误先修执行链；上下文错误先测试skill；能力缺口才优先增加合格纠正数据和后训练；未知项先分配诊断预算。这个顺序不是保证最优的定理，应与固定数据扩充基线比较总收益和成本。

辅助诊断器的版本、提示词、判据和校准样本单独留档。发生分歧时保留原始物理证据与人工/独立判据，不用反复改提示词直到输出“通过”。这使VeriFine式判断器改进成为可审计的研究变量，而不污染固定的驾驶验收。

## 时间与模态契约

在线技能的每份输入应有source、timestamp和available_at，执行时按当前决策时间裁剪；禁止把7秒离线caption、未来白膜或反事实评分缓存作为当前可观测记忆。离线生成可以使用特权未来，但其产物用途必须是监督/诊断。AUGUstus沿用原生4帧历史与8个未来点；ChainFlow的10个未来点是另一个消费者协议，不能为了统一平台而悄悄改变原生时间定义。各模型共享证据引用和任务生命周期，不强制共享监督张量。
