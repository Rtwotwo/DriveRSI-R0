# 有界的全流程自动执行

入口仍为 `driversi.rsi.experiments.continual_curriculum auto`。默认保留小规模参数；明确指定 `--max-problems` 可以覆盖冻结的整个问题队列，不再硬编码最多3个问题。`--max-transitions` 最多为每个允许问题64次，总墙钟预算仍最多24小时，每个原生阶段有自己的执行预算。预算耗尽会如实结束，不能解释为问题已解决。

生成不足时，现有恢复器读取已结算的拒绝原因并调整策略；低产、重复或来源尝试耗尽可触发扩源，最高同时10个来源，耗尽来源可在同一候选池内替换。总配额模式为50条、每个参与来源至少1条，因此剩余尝试资格也按1条计算。位置和航向不参与选择。未知在途结果必须核清，不能靠启动下一任务绕过。

累计去重后通过轨迹、图像和监督准入的50条数据进入原生纯合成SFT。首轮50条×4次曝光、batch=2、GPU6、100次更新，学习率由原生优化器按批量规则计算，初始缩放基准约3.5355e-5。具体以训练配方与原生训练回执为准。PDMS>.95、源位姿PSNR>25dB不变。

目标回测仍为0：按现有学习预算准备下一轮，新训练批次仍为50条，其中至少10条不得出现在任何此前目标失败的训练输入中。最多40条已消费数据作为该批的复用样本；所有历史合格轨迹继续参与去重，不能把未选入训练的旧轨迹重新生成来凑数。累计数据量增长，不把下一批描述为100条联合训练。目标改善：完成原生配对全量12146场景评测，通过全局均分、安全子项、新增零分、旧问题保持及配对收益检查后晋级；不通过保留父模型，记录原因，继续其他问题。晋级后下一问题从新父模型启动；同时用完整评测标记已被迁移解决的排队问题。

部署期间使用 `driversi.rsi.experiments.curriculum_handoff`：指定正在运行的旧控制器PID、同一campaign、其automatic/下的一次性交接目录、队列/转换预算和原绝对deadline。只创建自己的阶段边界停止标记，等待旧进程退出和结果结算，随后在同一锁内继续。等待也消耗原有时间预算，不清空数据、不终止原生子任务、不恢复桌面自动监控。

测试中的模拟阶段只证明控制流，包括不足→修订→训练→目标失败→再训练→全量结算→下一问题，不是实际训练收益。最终仍需真实的训练、全量评测和晋级回执。
