# AUGUstus 新分支与技能记忆试验

当前实现可以执行新的 DriveRL 推演、生成同分支 AUGUstus 监督预览、对合格样本构建原生混合缓存，并记录实际生成成本。它没有完成本轮学生配对训练和收益验证。

## 执行边界

`generation_schedule` 将三种模式区别限定为前置检查：无记忆不调用可选接触预检；固定流程始终预检；记忆模式只在历史案例的接触证据及附近对象条件都适用时预检。三者均使用冻结 DriveRL 生成新历史和未来，后置轨迹、物理、视觉和语言准入完全相同。这个对照检验程序选择，不是三种训练策略的收益实验。

实际 v1 在新推演中发现：只共享“自车运动、近似直行”的案例会误触发接触预检。v2 增加附近对象条件；不满足前提的记忆仍留档但不执行技能。该修改没有证明检索准确率或驾驶能力提升。

## 原生联合监督

`driversi_agents.augustus.branch_supervision.diagnostic_preview` 从真实执行与对应渲染产物导出四帧历史、三相机原生拼接视频，以及八个半秒间隔的实际未来位姿。未来图像不进入当前策略输入。当前框和 t+4s 对象身份构成 prediction 语言草稿；不是复用原日志的未来标签。

标签采用显式的新数据标注协议：当前50m内可投影对象，每个身份选最大可见视图；未来自车坐标系，距离10/30m划分near/middle/far，左右2m划分front，身后为behind。这些阈值不是声称复现未公开的AutoDrive-P3标注规则。遮挡、框位置、身份连续性必须复核；缺未来身份或近裁剪面歧义时拒绝。

`publish` 先复核独立视觉准入与语言审核，才生成HF缓存。诊断预览不能进入训练。已有导出续用必须包含完整的scene、rollout、render和原日志哈希，并匹配实际parent与anchor，禁止仅比对两个文件表的交集。

`build_training_pair` 只接受已准入样本。控制组保留同一原数据池，干预组增加合格合成行；更新预算仍由统一生命周期指定。schema2 `augustus_joint_cache`封存原manifest、原缓存、样本准入以及混合缓存文件。原生加载器逐行比对混合数据与封存来源，包括视频和语言字段。旧的原锚点relabel入口禁止消费这种数据，避免抹去分支准入血缘。

## 本轮实际边界

两个执行窗口来自同一Singapore日志，新的DriveRL轨迹分别为98.5670和97.4082反事实PDMS，无接触且恢复一致。四个其他准备尝试因路线支持拒绝。不能称为多来源难例纠正；也没有证明AUGUstus在这些场景失败。

一份新分支完成60张GS图片及原生监督预览，但全部15个渲染时间点的ego高程未通过，独立视觉准入尚未取得。实际配对数据入口拒绝这份预览，没有创建训练缓存或启动优化器。

三组v1及修正后的记忆v2均重新运行物理世界，每组500个Harness记账sim-agent steps；三组v1教师分数相同。生成成本保存在记忆中，与渲染/标注/训练/评测成本分开，不能当作端到端总成本。最初采集器误读`stages.consumed`产生0步，原记录保留，`results-verified.json`依据权威Harness500步记录纠正；活动库使用`cases-verified.sqlite`。v2直接读取正确字段。

尚未完成：合格视觉样本、AUGUstus实际配对训练与独立navtest评测、由真实训练回执支持的技能收益回写。没有运行navtrain学生评分，没有改原生模型/loss/准入，没有晋级模型。未对任何新场景宣称学生能力改善。
